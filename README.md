# موقع فهد المشعان — FAHAD ALMISHAN

موقع شخصي/تجاري كامل (Next.js 14 + TypeScript + Tailwind + Framer Motion + Supabase)
مع لوحة تحكم خاصة بالمشرف على `/admin`.

---

## 1) التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # ثم عبّئ القيم كما في القسم التالي
npm run dev
```

افتح: http://localhost:3000
لوحة التحكم: http://localhost:3000/admin

---

## 2) إنشاء مشروع Supabase

1. اذهب إلى https://supabase.com → New Project.
2. اختر كلمة مرور لقاعدة البيانات واحفظها.
3. بعد إنشاء المشروع، من **Settings → API** انسخ:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (سرّي جدًا، لا يوضع في الفرونت-إند أبدًا)

---

## 3) إعداد قاعدة البيانات

من لوحة Supabase → **SQL Editor** نفّذ الملفين بالترتيب:

```
supabase/schema.sql   -- الجداول + سياسات RLS
supabase/seed.sql     -- تعبئة الخدمات الإحدى عشرة بكل تفاصيلها
```

**مهم جدًا (نموذج الصلاحيات):** بما أن الموقع لمشرف واحد فقط، سياسات RLS تعتبر
أي مستخدم "authenticated" (مسجّل دخول عبر Supabase Auth) هو المشرف. لذلك:
- **لا تُنشئ أي حساب مستخدم آخر في Supabase Auth لهذا المشروع أبدًا.**
- حساب المشرف الوحيد هو الذي ستنشئه في الخطوة التالية.

---

## 4) إنشاء حساب المشرف

من لوحة Supabase → **Authentication → Users → Add User**:
- البريد: نفس القيمة التي ستضعها في `ADMIN_EMAIL` (مثال: `ff2h2d1994@gmail.com`)
- كلمة مرور قوية من اختيارك
- فعّل "Auto Confirm User"

هذا هو الحساب الوحيد الذي يمكنه الدخول إلى `/admin` — الموقع يتحقق من تطابق
البريد مع `ADMIN_EMAIL` في كل من الـ middleware والـ Server Actions.

---

## 5) إعداد Supabase Storage

من **Storage** أنشئ Bucket باسم:

- `media` → Public bucket (لصور/فيديوهات الأعمال والشعار)
- `uploads` → Public bucket (للملفات المرجعية التي يرفعها العميل في نموذج الطلب)

بعد إنشاء كل Bucket، من تبويب **Policies** أضف:
- للقراءة العامة (SELECT): `true` لكل الزوار.
- للرفع (INSERT):
  - `media`: للمستخدمين المسجلين فقط (`auth.role() = 'authenticated'`) — أي المشرف.
  - `uploads`: للجميع (`true`) — لأن العميل يرفع ملفات مرجعية قبل تسجيل الدخول.

## 6) إعداد Environment Variables

انسخ `.env.example` إلى `.env.local` (محليًا) وإلى إعدادات المشروع في Vercel (للنشر):

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_EMAIL=
NEXT_PUBLIC_SITE_URL=
NEXT_PUBLIC_WHATSAPP_NUMBER=966531166659
NEXT_PUBLIC_CONTACT_EMAIL=ff2h2d1994@gmail.com
```

لا تضع أي مفتاح داخل الكود أو GitHub — استخدم فقط ملفات البيئة/إعدادات Vercel.

---

## 6.1) رسالة الخطأ "Your project's URL and Key are required"

إذا رأيت هذه الرسالة (على Netlify أو أي منصة نشر)، فهذا يعني أن متغيرات
`NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` غير مضافة في
إعدادات تلك المنصة تحديدًا. كل منصة استضافة (Vercel، Netlify، إلخ) تحتاج
إضافة متغيرات البيئة بشكل منفصل من لوحتها الخاصة — إضافتها في `.env.local`
على جهازك لا تنقلها تلقائيًا لأي استضافة سحابية. الحل: افتح إعدادات
Environment Variables في منصة النشر التي تستخدمها وأضف نفس القيم الموجودة
في `.env.example`، ثم أعد النشر (Redeploy). هذا الدليل مكتوب لنشر المشروع
على **Vercel تحديدًا** (القسم 7) لأنه الأكثر توافقًا مع Next.js App Router؛
إذا كنت تستخدم Netlify بدلاً منه، الخطوات نفس الفكرة لكن من لوحة Netlify.

## 7) النشر على Vercel

1. ادفع المشروع إلى مستودع GitHub خاص بك.
2. من https://vercel.com → New Project → اختر المستودع.
3. أضف كل متغيرات البيئة من الخطوة 6 في **Settings → Environment Variables**.
4. اضغط Deploy.

## 8) ربط الدومين

من إعدادات المشروع في Vercel → **Domains** → أضف دومينك واتبع تعليمات DNS.
بعد ربط الدومين، حدّث `NEXT_PUBLIC_SITE_URL` بالدومين الفعلي وأعد النشر — سيتحدث
تلقائيًا كل من: روابط SEO، sitemap.xml، وQR Code في الصفحة الرئيسية.

## 11) نسخة احتياطية من البيانات

أسهل طريقة: من لوحة Supabase → **Database → Backups** (نسخ تلقائية حسب خطتك)،
أو يدويًا من **SQL Editor** بتصدير الجداول:

```sql
-- مثال: تصدير جدول الأعمال كـ JSON

```

يمكنك أيضًا استخدام `pg_dump` عبر connection string الموجود في
Settings → Database إذا احتجت نسخة كاملة من قاعدة البيانات.

## 12) بنية المشروع (ملخص)

```
app/
  layout.tsx              ← الجذر: الخطوط + اللغة
  (site)/                 ← الموقع العام (Header/Footer عام)
    page.tsx              ← الرئيسية
    services/, services/[slug]/
    portfolio/, portfolio/[slug]/
    about/, contact/, request/
  admin/                  ← لوحة التحكم (محمية بالكامل)
    login/, projects/, services/, requests/, settings/
lib/
  supabase/               ← عملاء Supabase (browser/server) + middleware
  actions/                ← Server Actions (كل الكتابة/الحذف تمر من هنا)
  data/                   ← جلب البيانات + قائمة الخدمات الاحتياطية
components/               ← عناصر الواجهة العامة ولوحة التحكم
supabase/
  schema.sql              ← الجداول + RLS
  seed.sql                ← تعبئة الخدمات الإحدى عشرة
middleware.ts             ← يحمي كل مسارات /admin
```

## 13) الحماية من الإزعاج/السبام (Rate Limiting) — جاهز، بدون حساب جديد

كل طلب عبر `/request` يمر تلقائيًا بحد أقصى 3 طلبات لكل عنوان IP خلال 10 دقائق،
باستخدام قاعدة بيانات Supabase نفسها (لا يحتاج أي خدمة خارجية). هذا يعمل من
اللحظة التي تشغّل فيها `schema.sql` — لا خطوة إضافية مطلوبة منك.

---

## 14) حماية الملفات المرفوعة — جاهز، بدون حساب جديد

كل من الواجهة (تحقق فوري قبل الرفع) وقاعدة بيانات Supabase Storage (تحقق فعلي
لا يمكن تجاوزه من المتصفح) يمنعان أي ملف خارج الأنواع الآمنة (صور/فيديو/PDF/Word/Zip)
أو أكبر من الحجم المسموح — أي ملف تنفيذي (.exe, .sh, .bat...) يُرفض تلقائيًا.
هذا التحقق مفعّل تلقائيًا عند تشغيل `schema.sql` المحدّث (القسم الخاص بـ
`storage.buckets` في نهاية الملف).

**إذا كنت شغّلت `schema.sql` القديم مسبقًا**، فقط شغّل هذا الجزء الإضافي من
نفس الملف (القسم الأخير "FILE TYPE / SIZE ENFORCEMENT") من جديد في SQL Editor
— لن يؤثر على أي بيانات موجودة.

## 15) Cloudflare Turnstile — الشيء الوحيد الذي يحتاج حسابًا منك

هذا هو الاستثناء الوحيد: Turnstile خدمة تابعة لـ Cloudflare، ولا يمكن لأي طرف
آخر (بما في ذلك أنا) إنشاء حساب باسمك — يتطلب بريدك وموافقتك على شروط
الخدمة. الكود جاهز بالكامل في `RequestForm.tsx` و`lib/actions/requests.ts`
وينتظر فقط مفتاحين منك (مجانًا، تقريبًا دقيقتين):

1. اذهب إلى https://dash.cloudflare.com وسجّل حسابًا مجانيًا (أو سجّل دخولك إن كان لديك واحد).
2. من القائمة الجانبية اختر **Turnstile** → **Add Site**.
3. أدخل دومينك (أو `localhost` للتجربة المحلية) واختر النوع **Managed**.
4. بعد الإنشاء، انسخ:
   - **Site Key** → ضعه في `NEXT_PUBLIC_TURNSTILE_SITE_KEY`
   - **Secret Key** → ضعه في `TURNSTILE_SECRET_KEY`
5. أعد تشغيل المشروع (أو أعد النشر على Vercel بعد إضافة المتغيرين).

**ملاحظة مهمة:** طالما `TURNSTILE_SECRET_KEY` فارغًا، الموقع يعمل بشكل طبيعي
بدون أي تحقق أمني إضافي (فقط حد الـ IP يعمل). بمجرد إضافة المفتاحين، يظهر
مربع التحقق تلقائيًا في نموذج الطلب ويُرفض أي إرسال بدون اجتيازه.

## 17) لوحة إدارة القوائم والألوان والأيقونات والأزرار

من `/admin/settings` أصبح بإمكانك التحكم بكل ما يلي بدون كتابة أي كود:

- **الشعار**: رفع شعار جديد مباشرة.
- **ألوان الهوية**: أربعة ألوان أساسية (الأزرق الكهربائي، البنفسجي، السماوي،
  البرتقالي) — تغييرها يُحدّث كل صفحات الموقع فورًا (الأزرار، التوهجات،
  التدرجات) لأنها مبنية على متغيرات CSS تُقرأ من قاعدة البيانات في كل تحميل صفحة.
- **القوائم (Navigation)**: أضف/احذف/أعد ترتيب/أخفِ أي رابط في قائمة التنقّل
  العلوية — بالعربي والإنجليزي معًا.
- **أزرار مخصصة**: أضف أي عدد من الأزرار (تظهر أسفل الصفحة الرئيسية) لأي رابط
  خارجي تحتاجه — عرض، حجز، ملف، إلخ — واحذفها وقتما تشاء.
- **أيقونات الخدمات**: من `/admin/services` اختر أيقونة كل خدمة من قائمة
  مصورة بدل كتابة اسمها يدويًا — يمنع أي خطأ إملائي.
- **الصور والفيديو**: من `/admin/projects` كما هو موضح في القسم 10.

كل هذه الإعدادات تُخزَّن في جدول `site_settings` نفسه — لا حاجة لأي تعديل إضافي
في `schema.sql`؛ أول مرة تحفظ فيها كل إعداد يُنشأ صفه تلقائيًا.

## 19) زر "إضافة عمل" الخاص بك فقط

كل بطاقة خدمة في الصفحة الرئيسية وصفحة الخدمات تُظهر الآن زرًا إضافيًا
بعنوان **"إضافة عمل (أنت فقط)"** — يظهر فقط عندما تكون مسجّلاً دخولك كمشرف
(تم التحقق من الجلسة على الخادم، وليس مجرد إخفاء بـ CSS). الضغط عليه يفتح
منتقي الملفات الأصلي لجهازك:

- على iPhone: الصور، التصوير المباشر، الملفات (وتظهر فيه Google Drive/Google
  Photos تلقائيًا إن كانا مثبّتين ومفعّلين كمزودي ملفات في iOS).
- على Android: نفس الفكرة عبر "Storage Access Framework" — أي تطبيق ملفات
  مثبّت (Google Drive، صور Google، إلخ) يظهر تلقائيًا في نافذة الاختيار.

هذا هو الحد الأقصى الذي يمكن لأي موقع ويب التحكم به — إظهار مزوّدين
معيّنين بالاسم داخل نافذة اختيار مخصصة غير ممكن تقنيًا من متصفح؛ فقط تطبيقات
الجوال الأصلية (native apps) تقدر تفعل ذلك. ما بنيته يستخدم أفضل طريقة
متاحة فعليًا على الويب.

بعد اختيار الملفات تُرفع مباشرة وتُنشأ كـ"عمل" جديد في معرض الأعمال بنفس
تصنيف الخدمة — يظهر للعملاء في `/portfolio` فورًا. العميل لا يرى هذا الزر
إطلاقًا، فقط يرى الأعمال المنشورة.

## 22) قائمة الأسعار

كل خدمة تعرض الآن نطاق سعر بالريال السعودي (مثال: "150 — 1500 ريال ·
حسب حجم وتعقيد المشروع") في بطاقتها وصفحتها التفصيلية. **تعديل السعر متاح
فقط من `/admin/services`** — لا يوجد أي طريقة للعميل لتعديله، والعميل يرى
السعر النهائي فقط أو "تواصل معنا" إذا عطّلت إظهار السعر لخدمة معينة.

**كيف حُددت الأرقام:** بحثت في السوق السعودي (منصتي خمسات ومستقل، وهما
المنصتان العربيتان الأكثر استخدامًا للعمل الحر، بالإضافة لأسعار شركات تصميم
مواقع محلية) وسعّرت كل خدمة عند مستوى **مستقل فردي** (وليس أسعار الوكالات
الكبيرة) لتكون في متناول الجميع مع هامش مرونة:

| الخدمة | السعر المقترح (ريال) | ملاحظة |
|---|---|---|
| خدمات الذكاء الاصطناعي | 150 – 1500 | حسب حجم وتعقيد المشروع |
| معالجة الصور | 30 – 250 | لكل صورة، حسب الكمية |
| التصميم الجرافيكي | 100 – 2000 | حسب نوع التصميم |
| خدمات الفيديو | 150 – 900 | حسب مدة الفيديو |
| الخدمات الصوتية | 75 – 400 | حسب مدة التسجيل |
| المواقع والبرمجة | 800 – 6000 | حسب نوع الموقع |
| تحليل البيانات | 50 – 400 | حسب حجم البيانات |
| التسوق الذكي | 40 – 150 | لكل طلب |
| حجز التذاكر والفنادق | 100 – 400 | حسب تعقيد الرحلة |
| استشارات وتدريب | 150 – 600 | للجلسة الواحدة |
| إدارة المحتوى | 300 – 1500 | شهريًا |

**بصراحة تامة:** فئات مثل "التسوق الذكي" و"حجز التذاكر" و"الاستشارات"
ليست خدمات لها سوق حر واضح بأسعار موثقة (على عكس التصميم والفيديو اللذين
وجدت لهما بيانات فعلية من خمسات ومستقل) — فسّعرتها بتقدير معقول يتماشى مع
الفئات المشابهة. عدّلها من لوحة التحكم حسب خبرتك الفعلية بتكلفة كل خدمة.

## 23) إصلاح: خطأ "Application error: a client-side exception"

كان هناك خلل فعلي مني: دالة التحقق من صلاحية المشرف (`getAuthorizedUser`)
كانت بلا معالجة أخطاء، وبعد إضافة زر "إضافة عمل" الخاص بالمشرف في القسم 19
أصبحت هذه الدالة تُستدعى في **كل زيارة للصفحة الرئيسية وصفحة الخدمات** —
فإذا كانت مفاتيح Supabase غير صحيحة أو غير مكتملة، كانت الدالة تتعطل
(throw) وتُسقط الصفحة بأكملها بدل أن تتجاهل الخطأ بهدوء.

تم إصلاحه: أي فشل في التحقق من صلاحية المشرف الآن يُعامل ببساطة كـ"هذا
ليس المشرف" بدل تعطيل الصفحة، في كل من `lib/utils.ts` و`middleware.ts`.
أضفت أيضًا صفحة خطأ احتياطية على مستوى الموقع بالكامل (`app/global-error.tsx`)
كخط دفاع أخير لأي خطأ غير متوقع مستقبلاً، بدل الرسالة الإنجليزية الافتراضية.

**هذا الإصلاح لا يغني عن التأكد من صحة متغيرات البيئة** (القسم 6) — فإن كانت
مفاتيح Supabase فعليًا خاطئة، ستستمر الميزات المرتبطة بها (تسجيل الدخول،
الطلبات، التقييمات) بعدم العمل، لكن الموقع لن يتعطل بالكامل بعد الآن.

## 24) الخطوط، الأسماء، والشعار

- **الخطوط** موحّدة الآن بالكامل على خط القوائم (IBM Plex Sans Arabic) في كل الموقع ولوحة التحكم — لا يوجد خط مختلف في العناوين بعد اليوم.
- اسم "فهد المشعان" في الصفحة الرئيسية أكبر وله حركة ظهور تدريجي (Fade + Slide)، وكذلك كل نصوص الواجهة الرئيسية (العنوان، الوصف، عبارة الهوية) — تظهر بالتتابع عند تحميل الصفحة، مع احترام كامل لإعداد "تقليل الحركة" (`prefers-reduced-motion`) لمن يفعّله.
- الشعار في الصفحة الرئيسية أكبر بكثير الآن (تقريبًا ضعف الحجم السابق) وأبرز بصريًا (توهج أقوى).

## 25) الألوان — لم يصلني الملف المرفق

قلت "مثل الصورة المرفقة" لكن لم تصل أي صورة مع رسالتك. عدّلت الألوان الافتراضية
لتكون أكثر سطوعًا ووضوحًا (أزرق حيوي `#0084FF`، بنفسجي حيوي `#A855F7`، سماوي
زاهٍ `#00E5FF`، برتقالي زاهٍ `#FF6B00`) بناءً على وصفك النصي فقط.

**مهم:** إذا كنت قد حفظت ألوانًا من قبل عبر `/admin/settings` → "ألوان الهوية
البصرية"، فهذا التغيير الافتراضي لن يظهر تلقائيًا (لأن قيمتك المحفوظة في
قاعدة البيانات لها الأولوية). في هذه الحالة افتح نفس الصفحة واضغط "حفظ
الألوان" بالقيم الجديدة، أو أرسل لي الصورة وسأضبطها بدقة أكبر.

## 26) حذف الصور والفيديو

من صفحة تعديل أي عمل (`/admin/projects/[id]/edit`) — مرّر فوق أي صورة أو
فيديو وستجد زر **×** أحمر صغير أعلى يمين الملف لحذفه فورًا. **ملاحظة دقيقة:**
هذا يحذف الملف من معرض الأعمال المعروض للعملاء مباشرة، لكن الملف نفسه يبقى
داخل مساحة تخزين Supabase (Storage) دون حذف فعلي منها — لا يظهر لأحد ولا
يؤثر على شيء، لكن إن أردت تفريغ المساحة تمامًا يمكنك حذفه يدويًا من لوحة
Supabase → Storage.

## 27) زر "إضافة عمل" وعداد الزوار — موجودان فعلًا

كلاهما مبني ويعمل، لكن كليهما يظهر **فقط بعد تسجيل الدخول كمشرف** — وهذا هو
سبب عدم ظهورهما لك حتى الآن على الأغلب:
- زر "إضافة عمل (أنت فقط)" يظهر أسفل كل بطاقة خدمة في الصفحة الرئيسية وصفحة
  الخدمات، فقط لجلسة المشرف المسجّلة.
- عداد الزوار (اليوم / آخر 7 أيام / الإجمالي) موجود في أعلى `/admin` (نظرة
  عامة) — ليس على الواجهة العامة، لأن عرض عدد الزيارات للعملاء ليس مناسبًا
  عادة لهوية "Premium AI" التي طلبتها في البداية. إذا كنت تريده ظاهرًا
  للعملاء أيضًا أخبرني وسأضيفه كقسم عام.

راجع القسم 4 أدناه لخطوات إنشاء حساب الدخول.

## 28) طرق الدفع

بحثت في السوق السعودي، وأسهل طريقتين لاستلام المبلغ **فورًا وبدون سجل تجاري
أو بوابة دفع** هما:
- **STC Pay** — محفظة رقمية، تحويل فوري بين المحافظ أو من أي بنك محلي.
- **تحويل بنكي (آيبان)** — عالمي، بدون أي رسوم على المستلم عادة.

لم أُضِف بوابة دفع ببطاقات (مثل Moyasar أو Tap) لأنها تتطلب سجلاً تجاريًا
واعتماد حساب تاجر — وهذا خارج نطاق موقع شخصي وقد يعطّل هدفك في "أسهل طريقة
لاستلام المبلغ".

**كيف تفعّلها:** من `/admin/settings` → قسم "طرق الدفع"، أدخل رقم STC Pay
والآيبان واسم البنك واسم صاحب الحساب، ثم فعّل "إظهار طرق الدفع للعملاء".
تظهر بعدها في صفحة `/contact` بأيقونة محفظة، والعميل يضغط لنسخ الرقم مباشرة.

## 29) تقييمات العملاء — تحقق إضافي

أعدت التحقق من الكود ولم أجد خللاً جديدًا. إذا استمرت المشكلة بعد تنفيذ
القسمين 3 و4 (تسجيل الدخول + إعادة تشغيل `schema.sql`)، أرسل لي لقطة شاشة
لرسالة الخطأ بالتحديد وسأحلها فورًا.

## 31) إعادة تصميم كاملة: كريمي/أبيض دافئ + ذهبي + أسود

هذا تغيير جذري وليس مجرد ألوان مختلفة — الموقع كان مبنيًا بالكامل كوضع داكن
(Dark Mode)، والصورة التي أرسلتها فاتحة/فاخرة (كريمي، ذهبي، أسود). لذلك:

- الخلفية الأساسية أصبحت كريمي دافئ بدل الأسود الداكن.
- كل نصوص الموقع أصبحت أسود دافئ بدل الأبيض.
- كل "الزجاج" (البطاقات الشفافة) وحدود العناصر أُعيد ضبطها بالكامل لتناسب
  خلفية فاتحة بدل الداكنة — كانت ستظهر شبه مختفية لو تركتها كما هي.
- الألوان المتحركة (الأزرق/البنفسجي/السماوي سابقًا) استُبدلت بذهبي وبرونزي
  ودرجة شمبانيا فاتحة، مبنية على نفس نظام الألوان الديناميكي في `/admin/settings`
  — يمكنك تعديلها من هناك في أي وقت.
- الشعار أُعيد تلوينه بتدرج أسود فحمي إلى برونزي إلى ذهبي بدل الأزرق سابقًا.
- عدّلت أيضًا ألوان رسائل النجاح/الخطأ (كانت فاتحة جدًا وتضيع على خلفية بيضاء).

**بصراحة:** لم أستطع مطابقة اللمسة الفنية الدقيقة في صورتك (المعدن ثلاثي
الأبعاد، الشرائط الذهبية المتموجة في الخلفية، الشارات الدائرية حول أرقام
الخدمات 01-11) لأن هذه عناصر رسم/تصميم يدوي وليست ألوان بسيطة — ما نفذته هو
نفس **لوحة الألوان** (Palette) بأمانة داخل نفس هيكلة الموقع الحالية. إذا
أردت الشكل المعماري نفسه (شارات دائرية، إطارات ذهبية حول كل بطاقة خدمة)
أخبرني وسأبني ذلك تحديدًا كخطوة تصميم إضافية.

## 32) وصف زر "إضافة عمل" بالتفصيل

الزر موجود أسفل كل بطاقة خدمة في الصفحة الرئيسية وصفحة الخدمات، بعنوان
**"إضافة عمل (أنت فقط)"** — ولا يظهر إلا وأنت مسجّل دخولك كمشرف. آلية عمله:

1. تضغط الزر → يفتح متصفح الجوال (Safari/Chrome) نافذة اختيار الملفات
   الأصلية لنظام التشغيل مباشرة — هذا نفس السلوك في أي موقع ويب، ولا يمكن
   لأي موقع تخصيصه أكثر من ذلك.
2. على **آيفون**: تظهر خيارات "التصوير الفوتوغرافي" (مكتبة الصور)، "تصوير
   فوري بالكاميرا"، و"تصفح" (Files) — ومن Files تظهر تلقائيًا أي حسابات
   سحابية مفعّلة لديك في التطبيق نفسه (iCloud Drive، Google Drive، إلخ) طالما
   ثبّتّها وفعّلتها كمصدر ملفات في إعدادات آيفون.
3. تختار صورة أو فيديو واحد أو أكثر (حتى 25 ميغابايت لكل ملف).
4. يرفعها الموقع تلقائيًا وينشئ بها "عملاً" جديدًا في معرض الأعمال بنفس
   تصنيف الخدمة التي ضغطت الزر من داخلها — يظهر للعملاء فورًا في `/portfolio`.
5. لاحقًا يمكنك من `/admin/projects` تعديل عنوان/وصف هذا العمل، أو حذف أي
   صورة منه (زر × كما في القسم 26).

هذا الشيء الوحيد الذي لا أقدر أفعله بدلاً عنك: الحساب يعيش داخل مشروع
Supabase الخاص بك تحديدًا، ولا أملك أي وصول إليه (ولا صلاحية تقنية لإنشاء
حسابات نيابة عنك حتى لو كنت أملك الوصول). الخطوات تأخذ أقل من دقيقتين:

1. افتح https://supabase.com/dashboard ودخول لمشروعك.
2. من القائمة الجانبية: **Authentication → Users → Add User**.
3. البريد الإلكتروني: يجب أن يطابق **تمامًا** قيمة `ADMIN_EMAIL` التي وضعتها
   في متغيرات البيئة على Netlify (افتراضيًا `ff2h2d1994@gmail.com` إن لم
   تغيّرها).
4. كلمة المرور: اختر أي كلمة مرور قوية تتذكرها أنت — لا أستطيع رؤيتها ولا
   اقتراحها نيابة عنك لأسباب أمنية.
5. فعّل **"Auto Confirm User"** قبل الحفظ.
6. ارجع لصفحة `/admin/login` وسجّل الدخول بنفس البريد وكلمة المرور.

- **محرر تخطيط الصفحات (Drag & Drop Page Builder)**: الحالي هو "لوحة إعدادات"
  تتحكم بالمحتوى والهوية والقوائم، وليس محرر Drag & Drop لموضع كل عنصر في
  الصفحة (ذلك يتطلب إعادة هيكلة الصفحات إلى نظام "أقسام قابلة للسحب"، وهو
  مشروع إضافي أكبر بكثير من إعدادات المحتوى).
- لم يتم اختبار المشروع فعليًا عبر `npm run build` في بيئتي لعدم توفر اتصال
  إنترنت لتثبيت الحزم — شغّله محليًا مرة قبل النشر (راجع القسم الأخير أدناه).

المشروع لم يُختبر فعليًا عبر `npm run build` في بيئتي، لأن بيئة العمل هذه لا
تملك اتصالاً بالإنترنت لتثبيت الحزم (قيد تقني في أدواتي، وليس شيئًا يمكن حله
بحساب أو صلاحية). راجعت الكود يدويًا بعناية (تطابق الأقواس، مسارات الاستيراد،
تطابق أسماء المكونات)، لكن الخطوة الوحيدة المتبقية فعليًا على جهازك هي:

```bash
npm install
npm run build
```

إن ظهر أي خطأ في هذه الخطوة أرسل لي نص الخطأ وسأصلحه فورًا.

كل ما عدا ذلك من القائمة التي طلبتها أصلًا — الصفحات، الأمان، RLS، Server
Actions، لوحة التحكم الكاملة، SEO، QR Code، RTL/LTR، وكل ما ورد في هذا القسم
(Rate limiting، حماية الملفات، Toast) — مبني ومفعّل وجاهز للتشغيل 100%.
